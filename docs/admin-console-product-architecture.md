# Operone 后台产品架构（CTO / 产品基线）

## 北极星

后台不是功能清单，而是让运营人员在一次工作流内完成“发现问题、判断原因、采取动作、验证结果”的系统。游戏、小说、漫画共享创作生命周期，但在质量、消费和生成媒介上保留各自的处置方式。

## 一级任务域

| 任务域 | 用户要完成的事 | 唯一入口 | 处置闭环 |
| --- | --- | --- | --- |
| 运营工作台 | 判断今天优先处理什么 | 概览 | 异常卡 → 对应队列/作品/路由 |
| 内容与质量 | 审核、修复、发布作品 | 待审队列、作品治理、样品馆 | 质量证据 → 编辑/重试/审核 → 再评估 |
| 增长与消费 | 增加创作与阅读/试玩转化 | 创作者漏斗、分发漏斗 | 漏斗断点 → 人群/作品入口 → 后续指标 |
| 商业与成本 | 管理权益、支付、模型成本 | 计费治理 | 收入、额度、账本覆盖、预算 → 审计 |
| 系统与 AI 运行 | 保证生成可用、可控、可追责 | AI 运行中心、系统健康、审计 | 服务商 → 场景路由 → 探测 → 队列 → 失败处置 |

## AI 运行中心

1. **API 服务商**：地址、凭据、模型目录、连通性探测。密钥只属于服务商，绝不伪装为业务模型。
2. **业务场景路由**：一张表表达所有执行策略：游戏规格、游戏视觉、游戏 BGM（LLM 降级）、小说正文、小说规划、漫画分镜、漫画/封面图、图像降级。每项都具备主模型与备用模型；语言覆盖是折叠的高级策略，默认继承。
3. **成本与保障**：价格规则、预算、账本覆盖率、调用成功率、延迟、最近探测与异常处置入口。

## 强制交付原则

- 配置项只有在实际请求路径读取后才允许显示为“生效”。
- 主备模型必须有实际执行级联；只展示输入框视为缺陷。
- 每个告警必须给出可点击的下一步，不以“红色数字”结束。
- 全部保存操作需区分草稿、待发布、线上生效；生产已有配置永不被代码默认值覆盖。
- 运营列表只展示工作所需的最小数据，创作者正文、提示词、密钥与上游响应不得外泄。

## 当前实施顺序

1. 完成场景级真实主备级联：文本、图像、BGM；统一模型调用账本。
2. 将 AI 运行中心拆为服务商、路由、成本与保障三个子页，并将语言覆盖收为每个场景的高级项。
3. 将概览改成异常优先的运营工作台，连接内容、增长、商业和系统的处置页。
4. 为游戏、小说、漫画分别给出质量/消费异常阈值与具体处置操作。
